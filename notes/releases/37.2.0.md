# blackbox-mod 37.2.0

Thomas's fork ([Maigre/blackbox-mod](https://github.com/Maigre/blackbox-mod)) of JOEBOX 1, the unofficial feature
mod for the **original 1010music Blackbox** (Mk1) on stock firmware **3.1.9**. Everything JOEBOX 1 has is still
there; this adds a fix for JOEBOX 1's restart loop and four things for Clip pads. TOOLS shows `37.2.0`.

**Status: a test release.** Every part passes the emulated suites (`./check.sh`: 31 suites, 0 failed), but
**Region, Loop Len, the Clip-mode waveform knobs and the install of this build's second file (`BBEXTRA.BIN`) have not
yet run on a unit.** That is the next bench gate (Gate 3). Also only emulated so far: the Slip knob's feel and sign
(new in 37.1.1) and the two fixes below. Slip itself was measured on a unit, to the sample (37.1.0d).

## New since JOEBOX 1

- **The restart loop is fixed.** JOEBOX 1 was put on hold because some units got stuck restarting after installing
  it. On the unit where it looped, the cause was one instruction: an exclusive load on memory that the stock firmware
  maps as device memory. With it gone that unit boots cleanly. The fix is also offered upstream (JOEBOX PR #2).
- **Slip on Clip pads**: a "Slip" row on a Clip pad's Pos tab, after Sync. It shifts what the clip plays against the
  clock, up to a bar either way, so a loop cut by ear sits where the groove wants it. Like a CDJ jog: clockwise pushes
  the loop ahead, counter-clockwise drags it behind. The value is beats.ticks, 960 ticks to a beat (`-0.480` is half
  a beat behind). Turn slowly for single ticks, fast for 1/64 steps; a turn stops on 0, pause to go past it. A change
  is heard at the next Sync step. 0 is stock.
- **Region on Clip pads**: a "Region" row before Slip: Auto, File or Loop. Loop plays only the pad's loop (Loop Start
  to Loop End, set in Sample mode or read from the WAV's own loop) as if it were the whole file, so a loop cut from a
  longer recording needs no Trim. Auto, the default, does that when the pad has a loop (Loop Mode on, and not the
  whole file) and plays the whole file otherwise. File always plays the whole file. Beat Count Auto counts the region,
  Slip shifts within it, and the end of the region crossfades into its start, so a region that is not a whole number
  of beats loops with no gap and no doubling. A change while the pad plays is heard the next time the loop comes round.
- **Loop Len on Clip pads**: a "Loop Len" row after Slip: Off, 1/16, 1/8, 1/4, 1/2, 1 bar, 2 bars or 4 bars. Only that
  much of the clip loops, in time, and it is the part that was playing when you turned it on, like a KP3's loop: 1/4
  repeats the beat that was playing. Changing the length keeps the start; Off goes back to the whole loop, in phase,
  as if it had played on all along. A length shorter than the pad's Sync step sets Sync to fit, and yours comes back
  when the length fits it again, or at Off. Works over Region and with Slip. **Needs the second file** (below).
- **Knobs on a Clip pad's waveform** (stock leaves all four blank in Clip mode): top-left Loop Start, top-right Loop
  End (the loop Region plays; one step is one pixel, so zoom in for finer steps), bottom-left Slip, bottom-right Loop
  Len. A white bracket shows the loop Region plays.
- **Fixed: a new file under a playing pad.** Loading a file into a Clip pad while it plays (the browser's pre-listen
  does this to the pad it was opened from, as do a load and a recording landing in the pad) no longer plays the new
  file with the old file's Slip, region or Loop Len, which could go silent past its end or play it shifted wrongly.
  For up to two Sync steps the new file plays as stock plays it, then as set.
- **Fixed: the pre-listen voice is no longer pad 2.** JOEBOX took the browser's pre-listen voice for pad 2: with pad
  2's Input on, the live input was mixed into every pre-listen; pad 2's insert effect ran on it; and every file you
  auditioned restarted pad 2's LFO 2 / 3 (Retrig, Once). None of that happens now.

All new rows are saved with the preset. At their defaults (Slip 0, Loop Len Off) the pads play as on JOEBOX 1, with
one exception: **Region starts on Auto**, so a Clip pad that has Loop Mode on and a loop shorter than the file now
plays only that loop. Set Region to File for the whole file.

## Install

1. You need **two files from the same build**: `BLACKBOX.bin` and `BBEXTRA.BIN`. Patched firmware images are not
   distributed. Make them from your own copy of 1010music's stock 3.1.9 `BLACKBOX.bin` (from
   <https://1010music.com/downloads>), either with the release's patch file, `python3 apply.py BLACKBOX.bin
   blackbox-mod-37.2.0.json` (it checks the stock file and the result by SHA-256 and writes both files), or from
   source: `RELEASE=1 ./build.sh && python3 patch.py solo slice duck chord cond filter cpu od comp seqfix fx2 munchi
   master fault cave` gives `out/<sets>/BLACKBOX.bin` and `out/BBEXTRA.BIN`.
2. Keep the stock `BLACKBOX.bin` somewhere safe: it is your way back.
3. Copy **both** files to the root of the microSD card.
4. With the Blackbox on its normal power supply, hold BACK + INFO while powering on, and let go when the install
   screen shows.
5. The first boot **restarts itself once**, a second or two in: that is the second file being written to the chip's
   second flash bank. Leave the card in and the power on until it is back up.
6. TOOLS shows **`37.2.0`**, with **no `!`** in front of the load figures (`62/75%`, not `!62/75%`).

A `!` means the second file is missing or from another build: Prism, Confetti, the insert effects and Loop Len are
then off (everything else works). Put the `BBEXTRA.BIN` that belongs with your `BLACKBOX.bin` on the card and power
off and on. A unit that ran an older two-file build needs this build's `BBEXTRA.BIN` too: the old one up there does not
match.

## Back to stock

Put 1010music's stock 3.1.9 `BLACKBOX.bin` on the card and install it the same way (BACK + INFO at power-on). The
second flash bank keeps this build's code, unused: stock firmware never looks at it, and it does not touch the unit's
calibration.

## Known issues

- **Not yet run on a unit**: Region, Loop Len, the Clip-mode waveform knobs, the bank-2 install (see Status).
- Slip, Region and Loop Len do nothing on Slicer pads, or on a Clip pad set to Sync Slice with slice markers. The
  playhead line on the waveform shows the position without Slip, region or Loop Len.
- A new file loaded into a playing Clip pad plays unslipped, without its region or Loop Len, for up to two Sync steps,
  then as set.
- Region: switching a Clip pad to Sample mode clears its loop points (stock does that). A Beat Count that is not Auto,
  including one read from the WAV, is taken as the region's length in beats. A pad that never loops round (Launch
  Trigger, or Loop Off), and a stopped pad, take a new region at their next launch. A region under half a beat counts
  0 beats on Beat Count Auto and Slip does nothing there: give it a Beat Count.
- Loop Len needs a Quant and a Sync (with either on None it does nothing), and a length of the whole loop or more
  does nothing. Set while a launch waits for its bar, it starts once the pad plays. A pad that stops forgets what it
  was looping: its next launch loops from the start of the clip. While it holds a shorter Sync the Sync row still shows
  yours, and turning that knob puts yours back for up to 43 ms. On a loop the length does not divide (a 3-beat loop
  with 1/2) the window starts over with the loop. Without the second file the row is there and saves, but does nothing.
- On the waveform, Loop Start turned all the way up to Loop End (or the other way) leaves no loop: the pad plays the
  whole file until they are apart again. With Region on File, or on Auto with Loop Mode None, the two knobs still move
  the loop points but nothing is heard and no bracket shows.
- JOEBOX 1's own known issues still apply (the README's list): the CPU can be spent in full (watch the load readout),
  LFO 2 / 3, ENV, the insert and Input are not on Granular pads, and presets from older mod builds can come back with
  a neighbouring Fidelity or delay Type.
