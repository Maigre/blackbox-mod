# blackbox-mod 37.4.0

Thomas's fork ([Maigre/blackbox-mod](https://github.com/Maigre/blackbox-mod)) of JOEBOX 1, the unofficial feature
mod for the **original 1010music Blackbox** (Mk1) on stock firmware **3.1.9**. This is **37.3.3 with Munchi's engine
moved to the chip's second flash bank**: everything 37.3.3 has is still there and sounds the same (Slip, Region, Loop
Len, Fit and Loop Fade on Clip pads, the knobs on a Clip pad's waveform, the Slip knob, Munchi and the rest of JOEBOX 1
rc4). What changes is where Munchi's code lives: 6.4 KB of the first flash bank are free again, the room the next
features need (the Looper, MIDI). TOOLS shows `37.4.0`.

**Status: a test release.** Every part passes the emulated suites (`./check.sh`: 31 suites, 0 failed). None of it has run on a
unit yet.

## New since 37.3.3

- **Munchi runs from the second flash bank.** Its engine (the granular delay, its reverb, the clock) moved there; the
  part that talks to the rest of the firmware stayed. Munchi's sound is the same to the bit: a scripted 27 s of Munchi
  (Wand, Random, Feedback, Freeze, Clock, Width, Duck, tempo changes, switching to and from it) gives every sample of
  JOEBOX 1 rc4's, and the suites keep a fingerprint of it.
- **6.4 KB of the first flash bank back** for what comes next. The first bank is where every feature's hooks must live,
  and it was nearly full.
- Munchi now needs the second file, as Prism, Confetti and the insert effects do (see Known issues).

The second file, `BBEXTRA.BIN`, changes with this release (it now holds Munchi's engine too).

## Install

1. You need **two files from the same build**: `BLACKBOX.bin` and `BBEXTRA.BIN`. Patched firmware images are not
   distributed. Make them from your own copy of 1010music's stock 3.1.9 `BLACKBOX.bin` (from
   <https://1010music.com/downloads>), either with the release's patch file, `python3 apply.py BLACKBOX.bin
   blackbox-mod-37.4.0.json` (it checks the stock file and the result by SHA-256 and writes both files), or from
   source: `RELEASE=1 ./build.sh && python3 patch.py solo slice duck chord cond filter cpu od comp seqfix fx2 munchi
   master fault cave` gives `out/<sets>/BLACKBOX.bin` and `out/BBEXTRA.BIN`.
2. Keep the stock `BLACKBOX.bin` somewhere safe: it is your way back.
3. Copy **both** files to the root of the microSD card, over the old ones if they are there.
4. With the Blackbox on its normal power supply, hold BACK + INFO while powering on, and let go when the install
   screen shows.
5. The first boot **restarts itself once**, a second or two in: that is the second file being written to the chip's
   second flash bank. It does so on every unit, 37.3.3 included, since their second file is not this one. Leave the
   card in and the power on until it is back up.
6. TOOLS shows **`37.4.0`**, with **no `!`** in front of the load figures.

A `!` means the second file is missing or from another build: Prism, Confetti, Munchi, the insert effects, Slip,
Region, Loop Len, Fit and Loop Fade are then off (Munchi's slot plays the plain delay), the waveform knobs are stock's
grey and the playhead line is stock's (everything else works). Put the `BBEXTRA.BIN` that belongs with your
`BLACKBOX.bin` on the card and power off and on.

## Back to stock

Put 1010music's stock 3.1.9 `BLACKBOX.bin` on the card and install it the same way (BACK + INFO at power-on). The
second flash bank keeps this build's code, unused: stock firmware never looks at it, and it does not touch the unit's
calibration.

## Known issues

- **Munchi needs `BBEXTRA.BIN`.** Without this build's second file, the delay Type list reads `---` where Munchi was,
  and a preset that uses Munchi plays the plain delay there until the right file is installed (it keeps its setting).
- **Not yet run on a unit**: in particular Munchi's load running from the second bank (same flash speed by the chip's
  design; under emulation the block costs 0.3 % fewer instructions) and the boot's longer pairing scan (609 flash words
  read sixteen times instead of 404).
- 37.3.3's known issues all still apply: `notes/releases/37.3.3.md`.

## Images (built locally; not in git)

Built 2026-10-18 with Arm GNU 14.2 from the commit that sets `src/release.h` to 37.4.0, on branch `rc4-sync` (37.3.3
with `feat/munchi-bank2`, `c3ccbb5`, merged in), full set `solo slice duck chord cond filter cpu od comp seqfix fx2
munchi master fault cave`, with `BANK2_NEW=1` (bank 2's code changed since 37.3.3). Bank-2 payload: id `0xa5adc22e`,
length `0x5bc0`, sum `0xe259f66e`, byte for byte the same in both builds; each `BLACKBOX.bin` carries that id and sum and
lets the card loader write bank 2. Bank 1 (`.cave`): 50 642 of 57 736 B in the release build (7 094 free),
51 282 in the dev build (6 454 free); `.bank2` 23 464 B.

The dev build (`37.4.0d`) also carries the bench's tools: its USB peek reads only the unit's memories and a few screen
registers, its poke writes only RAM, and a parameter mailbox lets the bench set a pad's rows as its knobs do. None of
that is in the release build, whose image is the same without them.

`apply.py` with `blackbox-mod-37.4.0.json` reproduces the release pair; a release build from this source with the
same toolchain gives the same bytes. Never put a dev build on a unit you lend or sell: its USB poke writes RAM, which
is enough to crash it.
