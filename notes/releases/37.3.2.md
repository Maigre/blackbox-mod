# blackbox-mod 37.3.2

Thomas's fork ([Maigre/blackbox-mod](https://github.com/Maigre/blackbox-mod)) of JOEBOX 1, the unofficial feature
mod for the **original 1010music Blackbox** (Mk1) on stock firmware **3.1.9**. This is **37.3.1 on JOEBOX 1 rc4**:
everything 37.3.1 has is still there (Slip, Region, Loop Len, Fit and Loop Fade on Clip pads, the knobs on a Clip
pad's waveform and their readable labels, the playhead on the frame heard, the Slip knob and the rest of JOEBOX 1),
now on top of JOEBOX 1's fourth release candidate (2026-10-17). TOOLS shows `37.3.2`.

**Status: a test release.** Every part passes the emulated suites (`./check.sh`: 31 suites, 0 failed). None of it
has run on a unit yet.

## New since 37.3.1 (all of it from JOEBOX 1 rc4)

- **The restart-loop fix is JOEBOX's own now.** The first JOEBOX 1 left some units restarting at the logo; this
  fork fixed that in 37.0.2, and rc4 fixes the same thing its own way, which replaces ours. Nothing changes on a unit
  that ran 37.3.1: neither build has the instruction that faulted.
- **USB with the compressor on Limit.** With the master compressor on Limit, the Blackbox could fail to show up on
  the computer over the power-jack USB (audio and MIDI): the limiter's look-ahead wrote over the request the computer
  had just sent. It no longer does.
- **New insert model names.** The Phaser's `Stone` is now `Pebble`, the Flanger's `Mistress` is `Electra` and `ADA`
  is `Jet`. Only the names changed: they sound the same, and presets saved before keep their models.

The second file, `BBEXTRA.BIN`, is **37.3.1's, byte for byte**: rc4 changes nothing in the chip's second flash bank.

## Install

1. You need **two files from the same build**: `BLACKBOX.bin` and `BBEXTRA.BIN`. Patched firmware images are not
   distributed. Make them from your own copy of 1010music's stock 3.1.9 `BLACKBOX.bin` (from
   <https://1010music.com/downloads>), either with the release's patch file, `python3 apply.py BLACKBOX.bin
   blackbox-mod-37.3.2.json` (it checks the stock file and the result by SHA-256 and writes both files), or from
   source: `RELEASE=1 ./build.sh && python3 patch.py solo slice duck chord cond filter cpu od comp seqfix fx2 munchi
   master fault cave` gives `out/<sets>/BLACKBOX.bin` and `out/BBEXTRA.BIN`.
2. Keep the stock `BLACKBOX.bin` somewhere safe: it is your way back.
3. Copy **both** files to the root of the microSD card, over the old ones if they are there.
4. With the Blackbox on its normal power supply, hold BACK + INFO while powering on, and let go when the install
   screen shows.
5. **From 37.3.1 or 37.3.1d** the second flash bank already holds this `BBEXTRA.BIN`: the unit starts straight up,
   with no restart (copying only `BLACKBOX.bin` is enough). **From 37.3.0 or earlier** the first boot **restarts
   itself once**, a second or two in: that is the second file being written. Leave the card in and the power on until
   it is back up.
6. TOOLS shows **`37.3.2`**, with **no `!`** in front of the load figures.

A `!` means the second file is missing or from another build: Prism, Confetti, the insert effects, Slip, Region,
Loop Len, Fit and Loop Fade are then off, the waveform knobs are stock's grey and the playhead line is stock's
(everything else works). Put the `BBEXTRA.BIN` that belongs with your `BLACKBOX.bin` on the card and power off and on.

## Back to stock

Put 1010music's stock 3.1.9 `BLACKBOX.bin` on the card and install it the same way (BACK + INFO at power-on). The
second flash bank keeps this build's code, unused: stock firmware never looks at it, and it does not touch the unit's
calibration.

## Known issues

- **Not yet run on a unit**: everything in this release (see Status).
- From JOEBOX 1 rc4's own notes: the power-jack USB does not work on every unit (on some, its data side is dead with
  any firmware, stock included); the machine Fidelity modes (SP1200, SP-12, MPC60, SP Raw, SP 45) can come out
  grittier on one hit than the next (JOEBOX's next build fixes it; this one does not have that fix).
- 37.3.1's known issues all still apply: `notes/releases/37.3.1.md`.

## Images (built locally; not in git)

Built 2026-10-17 with Arm GNU 14.2 from the commit that sets `src/release.h` to 37.3.2, on branch `rc4-sync` (`halo`
at 37.3.1 with upstream `main` at JOEBOX 1 rc4, `66329ad`, merged in), full set `solo slice duck chord cond filter
cpu od comp seqfix fx2 munchi master fault cave`; the dev build (`37.3.2d`) from the commit after it that makes its
room (rc4 had left it 32 B over: the dev-only mailbox and peek made smaller, the same behaviour, D-027), which leaves
the release build byte for byte as it was. Bank-2 payload: id `0xce1ead5b`, length `0x4180`, sum `0xc6b2bdbc`,
37.3.1's byte for byte and the same in both builds; each `BLACKBOX.bin` carries that id and sum. Bank 1 (`.cave`):
57 072 of 57 736 B in the release build (664 free), 57 712 in the dev build (24 free); `.bank2` 16 724 B.

The dev build (`37.3.2d`) also carries the bench's tools: its USB peek reads only the unit's memories and a few screen
registers, its poke writes only RAM, and a parameter mailbox lets the bench set a pad's rows as its knobs do. None of
that is in the release build, whose image is the same without them. On a unit on 37.3.1d it too starts with no
restart (the same `BBEXTRA.BIN`).

`apply.py` with `blackbox-mod-37.3.2.json` reproduces the release pair; a release build from this source with the
same toolchain gives the same bytes. Never put a dev build on a unit you lend or sell: its USB poke writes RAM, which
is enough to crash it.
