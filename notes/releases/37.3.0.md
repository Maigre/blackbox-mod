# blackbox-mod 37.3.0

Thomas's fork ([Maigre/blackbox-mod](https://github.com/Maigre/blackbox-mod)) of JOEBOX 1, the unofficial feature
mod for the **original 1010music Blackbox** (Mk1) on stock firmware **3.1.9**. Everything JOEBOX 1 has is still
there, with everything 37.2.0 added (the restart-loop fix, Slip, Region, Loop Len and the knobs on a Clip pad's
waveform). This release adds **Fit** and **Loop Fade** to Clip pads, a smoother Slip knob, and fixes for what the first
session on a unit found. TOOLS shows `37.3.0`.

**Status: a test release.** Every part passes the emulated suites (`./check.sh`: 31 suites, 0 failed). 37.2.0's
Region, Loop Len, waveform knobs and second-file install have now run on a unit (the first test session, 2026-10-16):
they measured right to the sample, and what that session found is answered here. **Nothing that is new in
37.3.0 has run on a unit yet**: Fit, Loop Fade, the Slip knob's new feel, the fixes, and the install of this build's
second file. That is the next test session.

## New since 37.2.0

- **Fit on Clip pads**: a "Fit" row on a Clip pad's Pos tab, after Loop Len: Off, Auto, 1/4, 1/2, 3 beats, 1 bar,
  6 beats, 2 bars, 4 bars or 8 bars. The loop (the Region, or the whole file) then lasts exactly that many beats at
  the tempo: it plays a little faster or slower, and its pitch moves with it (it is not a time-stretch). A loop cut by
  ear that is not a whole number of beats no longer stutters at every Sync step, and a WAV's own Beat Count no longer
  chops a shorter Region. Auto takes the nearest whole number of beats (14.015 beats plays as 14, 3.74 as 4), counted
  once for each loop length: change the tempo and the loop keeps its beats and follows. A length that is not a whole
  number of bars (3, 5, 7 or 14 beats) is a polyrhythm: the loop comes round every so many beats against the bar, each
  pass in time and seamless. A change while the pad plays is heard the next time the loop comes round. Off is stock.
- **Loop Fade on a Region**: Sample mode's Loop Fade row is on a Clip pad's Pos tab too, after Fit. On a pad playing
  a Region it smooths the loop point as Sample mode does (the end of the loop crossfades into the audio just before
  Loop Start), so a loop whose end and start do not meet no longer clicks each time it comes round. 0 is stock.
- **The Slip knob, smoother.** It speeds up smoothly as you turn faster, from single ticks when slow to 1/64 steps
  (60 ticks) at full speed, with no steps you can feel in between. 0 is a detent: a turn stops there for a moment and
  then goes on if you keep turning, longer when you come in slowly (0.4 s, so a slow approach no longer runs past 0),
  shorter when fast (0.15 s).
- **Fixed: the names of the knobs on a Clip pad's waveform** were too long and hid the values. They read `LpS`,
  `LpE`, `Slip` and `LpLen` now, and positions of up to eight digits stay clear of the next knob.
- **Fixed: Region Auto follows the loop points** in Clip mode. A take whose loop points were moved on the Clip pad's
  waveform stayed on the whole file, because Auto also asked Sample mode's Loop Mode, a row a Clip pad never shows.
- **Fixed: Loop Len takes the value the knob rests on**, about 0.2 s after it stops. Turning from Off to 1/4 used to
  take the 1/16 it passed on the way, so the loop started off the beat and Sync was forced to 1/16. A slow
  step-through still takes each value in turn, and Off is immediate.
- **Fixed: a loop made longer from a very short one** (under half a beat) waited for a stop and a new launch. It now
  starts the next time round, and falls into time over one pass.
- **Fixed: the waveform's length.** On a pad whose file another pad also names (the browser loads its files into the
  pad it was opened from), the top-right knob stopped short of the end of the file, the loop bracket did not show, and
  the view stopped following the playhead part-way through the loop. The screen now uses the pad's own file length.
- **Fixed: a pad stuck after the file browser.** Leaving the browser gives the pad its own file back; if the file it
  had been auditioning was longer and the pad was in its last part, the pad played only its first beat, once each
  time round, until it was stopped. It now plays on from its next pass, in time.
- **Changed: Slip and Region need the second file too**, as Loop Len already did (the space for Fit and Loop Fade came
  from moving the Clip pads' code to the chip's second flash bank). Without this build's `BBEXTRA.BIN` every Clip pad
  plays exactly as on stock.

All new rows are saved with the preset. At their defaults (Slip 0, Loop Len Off, Fit Off, Loop Fade 0) the pads play
as on JOEBOX 1, with one exception, as in 37.2.0: **Region starts on Auto**, so a Clip pad whose loop points are not
the whole file plays only its loop. Since this release that holds whatever Sample mode's Loop Mode says. Set Region to
File for the whole file.

## Install

1. You need **two files from the same build**: `BLACKBOX.bin` and `BBEXTRA.BIN`. Patched firmware images are not
   distributed. Make them from your own copy of 1010music's stock 3.1.9 `BLACKBOX.bin` (from
   <https://1010music.com/downloads>), either with the release's patch file, `python3 apply.py BLACKBOX.bin
   blackbox-mod-37.3.0.json` (it checks the stock file and the result by SHA-256 and writes both files), or from
   source: `RELEASE=1 ./build.sh && python3 patch.py solo slice duck chord cond filter cpu od comp seqfix fx2 munchi
   master fault cave` gives `out/<sets>/BLACKBOX.bin` and `out/BBEXTRA.BIN`.
2. Keep the stock `BLACKBOX.bin` somewhere safe: it is your way back.
3. Copy **both** files to the root of the microSD card, over 37.2.x's if they are there.
4. With the Blackbox on its normal power supply, hold BACK + INFO while powering on, and let go when the install
   screen shows.
5. The first boot **restarts itself once**, a second or two in: that is the second file being written to the chip's
   second flash bank. It does so on a unit that ran 37.2.0 or 37.2.1 too, since their second file is not this one.
   Leave the card in and the power on until it is back up.
6. TOOLS shows **`37.3.0`**, with **no `!`** in front of the load figures (`62/75%`, not `!62/75%`).

A `!` means the second file is missing or from another build: Prism, Confetti, the insert effects, and Slip, Region,
Loop Len, Fit and Loop Fade on Clip pads are then off (everything else works). Put the `BBEXTRA.BIN` that belongs
with your `BLACKBOX.bin` on the card and power off and on.

## Back to stock

Put 1010music's stock 3.1.9 `BLACKBOX.bin` on the card and install it the same way (BACK + INFO at power-on). The
second flash bank keeps this build's code, unused: stock firmware never looks at it, and it does not touch the unit's
calibration.

## Known issues

- **Not yet run on a unit**: everything new in this release (see Status).
- Without this build's `BBEXTRA.BIN`, Slip, Region, Loop Len, Fit and Loop Fade are there and save, but do nothing;
  the Slip row then shows a plain number of ticks and turns like any number row, and the waveform shows no loop
  bracket (its four knobs still turn: Loop Start and Loop End move the loop points, which the pad then does not play).
- Slip, Region, Loop Len and Fit do nothing on Slicer pads, or on a Clip pad set to Sync Slice with slice markers.
  The playhead line on the waveform shows the position without Slip, Region or Loop Len.
- A new file loaded into a playing Clip pad plays unslipped, without its region or Loop Len, for up to two Sync steps,
  then as set.
- Region: switching a Clip pad to Sample mode clears its loop points (stock does that). A Beat Count that is not Auto,
  including one read from the WAV, is taken as the region's length in beats (Fit overrides it). A pad that never
  loops round (Launch Trigger, or Loop Off), and a stopped pad, take a new region at their next launch. A region under
  half a beat counts 0 beats on Beat Count Auto and Slip does nothing there: give it a Beat Count, or use Fit.
- Loop Len needs a Quant and a Sync (with either on None it does nothing), and a length of the whole loop or more does
  nothing. A pad that stops forgets what it was looping: its next launch loops from the start of the clip. While it
  holds a shorter Sync the Sync row still shows yours. A slow, steady turn (about 0.2 s on each value) can take the
  values it passes. Turned Off and on again within two Sync steps of a new file loaded into the playing pad, it can
  take its in-point from the old file's window.
- Fit changes the speed, so the pitch (3.74 beats fitted to 4 plays 6.5 % slower and a little lower). The Beat Count
  row and the clip length the app shows stay stock's. After a tempo change the pad follows within 43 ms; the step
  already under way finishes at the old tempo. A fitted loop at another speed than its own costs more CPU. Fit has no
  knob on the waveform screen. Auto's count is kept while the pad's file stays open: a preset at another tempo that
  plays the same file may keep the count made at the old tempo; play a pass on another Fit value, then Auto, to count
  again.
- Loop Fade does nothing on a loop that starts at the very beginning of the file, on a whole file, on a pad that never
  loops round, on a loop under 2 048 samples, in Fidelity's machine modes, above about four times the speed, or while
  Loop Len is on. The row also shows on Clip pads where it does nothing. Whether the card keeps up with a long fade
  (the pad reads its file in two places while it plays) is not yet measured.
- On the waveform, Loop Start turned all the way up to Loop End (or the other way) leaves no loop: the pad plays the
  whole file until they are apart again. With Region on File the two knobs still move the loop points but nothing is
  heard and no bracket shows.
- JOEBOX 1's own known issues still apply (the README's list): the CPU can be spent in full (watch the load readout),
  LFO 2 / 3, ENV, the insert and Input are not on Granular pads, and presets from older mod builds can come back with
  a neighbouring Fidelity or delay Type.

## Images (built locally; not in git)

Built 2026-10-16 with Arm GNU 14.2 from the commit that sets `src/release.h` to 37.3.0, on branch
`37loop/blackbox-t-021`, full set `solo slice duck chord cond filter cpu od comp seqfix fx2 munchi master fault cave`,
with `BANK2_NEW=1` (bank 2's code changed since 37.2.1). Bank-2 payload: id `0x2a0e4094`, length `0x4120`, sum
`0x2cbfbf38`, byte for byte the same in both builds; each `BLACKBOX.bin` carries that id and sum and lets the card
loader write bank 2 (`b2load_writes` = 1). Bank 1 (`.cave`): 56 616 of 57 736 B in the release build, 56 744 in the
dev build; `.bank2` 16 652 B.
